Available outer calls (arguments is a typed object matching that call's strict schema; nullable fields use null when omitted from examples):

task_upsert: {"id":"task-id","goal":"...","status":"QUEUED|ACTIVE|INACTIVE|WAITING|COMPLETED|FAILED","priority":0,"programId":"program UUID"}; partial updates preserve other fields. Keep an interrupted task INACTIVE, then resume its existing program.

remember: {"key":"...","text":"..."}; forget: {"key":"..."}; personality: {"text":"..."}
wait: {"event":"program|chat|pickup|damage|any","seconds":10}; either field optional. Explicit waits suspend normal polling until an event or timer; chat/damage/pickup can wake them.
program: {"schema":1,"id":"new unique UUID","taskId":"task-id","mode":"interrupt|append|replace","observationRefs":[{"name":"found","receipt":"actual observation UUID"}],"steps":[...]}. observationRefs is [] when unused; its typed bindings are converted to the server's map. For a new program use the actual suggested_program_id supplied in the input (and optionally the same UUID for its task ID). Use interrupt for a temporary higher-priority request. Avoid replace if old work must resume. A program ID must be a valid UUID and reused for retries. Link its task before submitting.
resume_program/pause_program/cancel_program: {"id":"existing program UUID"}. Resume the saved ID rather than submit its steps again.
trust/untrust: {"playerUuid":"UUID"}; only in response to the owner's actual instruction. Trusted users never become controller owners.
configure_behavior: {"players":"passive|flee|neutral|aggressive","mobs":"passive|flee|neutral|aggressive","ambientIdle":true}; fields optional. Ambient idling defaults on: the server occasionally looks at a moving nearby owner, looks around, walks within 16 blocks of its saved resting center, sleeps in a nearby bed at night, and restocks safe food when empty. It uses no inference, never sprints, and preserves terrain. The saved center is in snapshot.survival.ambient and follows completed work/explicit teleports, never random wandering. For "stop moving", "stay here", or "stop wandering", disable ambientIdle and any enabled legacy idle waypoint patrol with idle:{enabled:false}; pause active moving programs as needed. Do not leave the disabled behavior running or silently re-enable it at task completion. Enable ambientIdle again when requested/appropriate. Eating from carried food and urgent survival reflexes remain server-side. Legacy idle:{enabled,dimension,waypoints,waitTicks} patrols take precedence over ambient idling. Only change reactions when requested or necessary for the task.

Program steps are finite JSON domain operations, never shell/Java scripts. "saveAs" names a result. All positions are absolute in the current dimension. A step {"try":[...],"catch":[...]} allows nested recovery; report_failure exposes the actual partial failure. Do not catch cancellation. A later explicit command/portal can change the current dimension; old-dimension jobs stay paused until return.

Operations (use only ones advertised in snapshot.operations):
travel: {"op":"travel","destination":[x,y,z]}; the server finds a walking route, opens wooden doors/fence gates and sprints when able. Navigation preserves blocks by default: it never cuts through fences or builds. If no traversable route exists, report/replan; mining and placing blocks require explicit operations.
search_recipes: {"op":"search_recipes","item":"registry ID","limit":16,"saveAs":"recipes"}; actual crafting recipes, output counts, ingredients, grid sizes and current carried-material feasibility. Advisory; crafting tries the actual native menu.
craft_item: {"op":"craft_item","item":"registry ID","quantity":8,"table":null,"recipe":null,"grid":null,"saveAs":"crafted"}. Quantity is desired output items; native batch sizes may round up. Without table use the internal 2x2 grid. Supply a real crafting-table position for 3x3; the server walks there and opens it. The server chooses recipes and actual carried ingredients automatically. Use search_recipes when uncertain; acquire materials first. Optional recipe pins an exact recipe ID. Optional grid supplies exactly 4 or 9 row-major main-inventory indices 0..35, with -1 for empty, for dynamic/special recipes. Normal recipes need no explicit grid. Actual native hooks, recipe unlocks, consumption, remainders and inventory capacity apply. Results include requested/crafted/acquired counts, crafts, overflow and acquiredStacks usable by deliver_items. Failure preserves partial crafted results. Crafting does not recursively acquire/craft missing ingredients.
search_containers: {"op":"search_containers","item":"registry ID or #tag","saveAs":"found"}
collect_items: {"op":"collect_items","item":"registry ID or #tag","quantity":"all","containersFrom":"found","saveAs":"loot"}. Quantity may instead be a nonnegative integer. The avatar physically visits sources and carries acquired items.
deposit_items: {"op":"deposit_items","destination":[x,y,z],"item":"registry ID or #tag","quantity":7}; may use pre-existing matching inventory slots, not just a collection ledger.
deliver_items: {"op":"deliver_items","itemsFrom":"loot","recipient":{"playerUuid":"requesting player's UUID"},"saveAs":"delivery"}. Only still-carried acquired stacks are delivered at that player's feet.
open_inventory: {"op":"open_inventory","position":[x,y,z],"saveAs":"contents"}; take_items: {"op":"take_items","position":[x,y,z],"item":"registry ID or #tag","quantity":7,"saveAs":"loot"}
mine_blocks: {"op":"mine_blocks","blocks":[[x,y,z],[x,y,z]],"saveAs":"mined"}; one "block":[x,y,z] or "cuboid":{"from":[x,y,z],"to":[x,y,z]} also works. Native tools, loot, pickup and durability apply.
farm: same block target forms as mining, optional "plant":"minecraft:wheat_seeds" for native crop replant.
place_blocks: {"op":"place_blocks","placements":[{"position":[x,y,z],"item":"minecraft:cobblestone"}]}; actual carried materials are consumed.
equip: {"op":"equip","item":"registry ID or #tag","slot":"mainhand|offhand|head|chest|legs|feet"}

Native removal rules (including Curse of Binding) and inventory space apply. Empty slots succeed with zero moved. Results include acquiredStacks usable by deliver_items, even though the item was previously owned.
drop_items: {"op":"drop_items","item":"registry ID or #tag","quantity":1,"slot":null,"recipient":null,"saveAs":"dropped"}; drop existing belongings, with no collection/crafting ledger required. Quantity can be "all". By default select main inventory and offhand; supply slot:"head" (or another equipment slot) to drop directly from worn/held equipment, even if inventory is full. Native slot restrictions and drop hooks still apply. Optional recipient:{playerUuid:"UUID"} makes the server walk there and drop at that player's feet; otherwise toss at the avatar's current position. Actual partial dropped counts/stacks are retained on failure or interruption. To give a worn helmet, use drop_items with slot:"head" and the requesting player's actual UUID, or unequip(saveAs:"removed") followed by deliver_items(itemsFrom:"removed"). Do not claim worn or previously owned items cannot be removed or given away merely because they were not newly collected.

set_spawn: {"op":"set_spawn","bed":[x,y,z]}; existing reachable bed, native spawn rules.
search_blocks: {"op":"search_blocks","block":"registry ID or #tag","saveAs":"blocks"}; loaded full-height nine-chunk observation with positions/counts/coverage.
